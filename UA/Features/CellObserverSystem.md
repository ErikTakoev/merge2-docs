# Cell Observer System (Система спостереження за клітинками)

Система спостереження за клітинками — це ключовий компонент архітектури Merge2, який дозволяє ігровим об'єктам (чіпам) та сервісам ефективно реагувати на зміни стану ігрового поля. Вона забезпечує відкладену (deferred) розсилку подій, що мінімізує кількість зайвих обчислень та гарантує стабільність стану під час обробки логіки.

## Основні компоненти

Система складається з трьох ключових сутностей:

### 1. [ChipChangedEvent](../../Core/Scripts/Field/CellObserver/ChipChangedEvent.cs)
Легка структура (struct), що описує одиничну зміну в конкретній клітинці сітки.

- **Властивості**:
    - `Cell Cell`: Клітинка, в якій відбулася зміна.
    - `Chip OldChip`: Чіп, що знаходився в клітинці до зміни (null, якщо клітинка була порожня).
    - `Chip NewChip`: Чіп, що знаходиться в клітинці після зміни (null, якщо клітинка тепер порожня).
- **Хелпери**:
    - `ChipAdded`: true, якщо чіп з'явився в раніше порожній клітинці.
    - `ChipRemoved`: true, якщо чіп був видалений або переміщений з клітинки.
    - `ChipReplaced`: true, якщо один чіп був замінений іншим в межах однієї клітинки.

### 2. [DeferredChipChangeNotifier](../../Core/Scripts/Field/CellObserver/DeferredChipChangeNotifier.cs)
Агрегатор подій, який накопичує всі зміни протягом поточного кадру (frame).

- **Відкладена обробка**: Замість негайної розсилки подій при кожній зміні (що може призвести до десятків викликів під час складних переміщень/злиттів), події збираються у чергу `pending`.
- **Злиття подій (Collapse)**: Якщо одна і та сама клітинка змінюється кілька разів за один кадр, система автоматично зливає ці зміни в одну подію, зберігаючи найперший `OldChip` та фінальний `NewChip`.
- **Flush**: Викликається один раз наприкінці кадру (зазвичай у `LateUpdate`), публікуючи весь пакет подій за один раз.

### 3. [CellObserverManager](../../Core/Scripts/Field/CellObserver/CellObserverManager.cs)
Центральний менеджер, який керує підписками `ICellSubscriber` та відповідає за точну доставку подій.

- **Двостороннє індексування**:
    - `cellToSubscribers`: Дозволяє миттєво знайти всіх підписників для конкретної клітинки.
    - `subscriberToCells`: Дозволяє швидко видалити всі підписки конкретного об'єкта при його знищенні.
- **Робота з Multi-cell чіпами**: При розсилці подій менеджер автоматично обчислює область (footprint), яку займав старий чіп та займає новий. Події отримують усі підписники, що спостерігають хоча б за однією клітинкою з цієї розширеної області.

## Пайплайн роботи (Workflow)

1. **Зміна стану**: `FieldGrid.SetChipInCell` викликається для зміни вмісту клітинки.
2. **Реєстрація**: `FieldGrid` звертається до `IChipChangeNotifier.Enqueue`, передаючи деталі зміни.
3. **Накопичення**: `DeferredChipChangeNotifier` додає подію в чергу або оновлює існуючу для цієї клітинки.
4. **Тріггер**: Наприкінці ігрового циклу (LateUpdate) викликається `notifier.Flush()`.
5. **Розсилка**:
    - `CellObserverManager` отримує список подій.
    - Для кожної події визначається зона впливу (з урахуванням розмірів чіпів).
    - Для кожного підписника в зоні викликається `OnObservedCellChipChanged(evt)`.

## Оптимізації

Система спроектована для роботи в умовах високої інтенсивності змін:

1. **Батчинг (Batching)**: Нотифікація відбувається один раз на кадр. Це гарантує, що підписники бачать фінальний сталий стан поля після всіх логічних маніпуляцій.
2. **Дедуплікація підписників**: Використовується `eventNotifiedSubscribers` (HashSet), щоб один підписник не отримував одну й ту саму подію кілька разів, навіть якщо він спостерігає за кількома сусідніми клітинками в зоні зміни.
3. **O(1) Операції**: Використання словників та хеш-сетів забезпечує миттєвий пошук підписників та злиття подій.
4. **Safe Callbacks**: Використовується `subscriberSnapshot` (List) для ітерації. Це дозволяє безпечно видаляти підписки (Unsubscribe) прямо під час обробки колбеку, не ламаючи колекцію.
5. **Мінімізація алокацій**: Усі допоміжні колекції (`snapshot`, `dedupe set`) перевикористовуються між кадрами та подіями, що запобігає зайвому навантаженню на Garbage Collector.

## Поточне використання

Основним механізмом використання є реалізація інтерфейсу `ICellSubscriber`.

### CellSubscriber
Базовий компонент, який дозволяє чіпу "бачити" своїх сусідів.
- Автоматично підписується на всі клітинки навколо чіпа (враховуючи його розмір).
- Перепідписується при переміщенні чіпа на нову позицію.

### PowerBoosterCellSubscriber
Спеціалізована версія для [ChipPowerBooster](../Chips/ChipPowerBooster.md).
- Використовує події від спостережуваних клітинок для виявлення генераторів навколо себе.
- Динамічно застосовує або знімає модифікатори прискорення, коли сусідні чіпи з'являються, зникають або змінюються.

### Інтеграційні тести
Система активно використовується в тестах (`ChipPowerBoosterTests`) для перевірки цілісності зв'язків та коректності виклику ефектів при складних маніпуляціях на полі.
