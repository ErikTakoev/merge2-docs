# Chip Relocation

[← На Головну](../Main.md) | [← Багато-клітинні Фішки](MultiCellChip.md)

Релокація — це механізм автоматичного переміщення фішок, що заважають, у сусідні вільні клітинки для звільнення місця під нову або переміщувану фішку. Це критично важлива система для підтримки геймплею з багато-клітинними фішками.

## The Problem
У грі з фішками різного розміру (1x1, 1x2, 2x2 тощо) часто виникають ситуації конфлікту простору:
1. **Злиття (Merge)**: Дві фішки 1x1 зливаються у фішку 1x2, якій потрібно більше місця.
2. **Перетягування (Drag)**: Гравець намагається поставити велику фішку у простір, де частково знаходяться інші фішки.

Без релокації гравцеві довелося б вручну розчищати місце, що погіршує UX.

## Technical Implementation

За логіку релокації відповідає клас `ChipMovingLogic`, який реалізує інтерфейс `IChipMovingLogic`.

### `CanChipMoving` Algorithm

Процес перевірки можливості переміщення та планування релокації відбувається наступним чином:

1. **Валідація Цільової Позиції та Виключень**:
   - Система перевіряє, чи валідна цільова клітинка (`leftTopCell`) для розміщення фішки заданого розміру (`fieldGrid.IsValidCellPos`).
   - Якщо передано опціональний набір `cellsToExclude`, цільова область не може перетинатися з цими клітинками, і вони також додаються до `unavailableCellsForRelocation`, щоб релоковані сусіди не займали заборонені зони.

2. **Визначення Конфліктів та Раннє Відсікання**:
   - Метод `PopulateOccupiedCellsInArea` збирає унікальні зайняті клітинки у перевикористовуваний буфер `occupiedCellsBuffer` без алокацій.
   - **Ліміт релокацій (`maxRelocations`)**: Якщо кількість знайдених конфліктних фішок `>= maxRelocations`, алгоритм негайно переривається (`return false`), уникаючи подальших перевірок та пошуку вільних клітинок. Якщо конфліктних фішок `0`, метод повертає `true` з `plannedRelocations = null` без виділення пам'яті.
   - Для кожної конфліктної фішки перевіряється **`chip.CanMoving()`** — якщо фішка є MoveLocked (наприклад, має блокуючий ефект `MoveLockedEffect`), весь процес негайно скасовується (`return false`): ні переміщення, ні релокації не відбувається.

3. **Сортування Пріоритетів**:
   - Фішки для переміщення сортуються за розміром (площею) у спадному порядку: `(bSize.x * bSize.y) - (aSize.x * aSize.y)`.
   - **Причина**: Великі фішки важче розмістити, тому для них шукають місце в першу чергу, щоб мінімізувати фрагментацію поля.

4. **Планування Переміщень (Simulation)**:
   - Створюється `plannedRelocations` (за точною кількістю конфліктів) — список запланованих дій.
   - Багаторазовий набір `unavailableCellsBuffer` заповнюється клітинками, що будуть зайняті новою фішкою (без проміжних алокацій через `fieldGrid.GetCells(..., clear: true)`).
   - Для кожної конфліктної фішки викликається `freeCellFinder.FindNearestFreeCell`.
   - **Важливо**: Якщо знайдено нове місце, його клітинки додаються до `unavailableCellsBuffer`, щоб наступні фішки в цьому ж циклі не намагалися зайняти те саме місце; після завершення буфери очищуються.

5. **Атомарність**:
   - Якщо хоча б для однієї конфліктної фішки не знайдено вільного місця, весь процес вважається неможливим (`return false`), і жодних змін на полі не відбувається.

### Batch Free Cell Search (`FindFreeCellsForChips`)

Для випадків, коли потрібно атомарно знайти вільні клітинки для масиву чіпів (наприклад, при генерації або тап-еволюції кількох фішок одночасно), `FreeCellFinder` надає метод `FindFreeCellsForChips(...)`:
- **Атомарність**: Перевіряє можливість розміщення **усіх** чіпів із списку. Якщо хоча б для одного чіпа вільна клітинка відсутня, метод повертає `false` і очищає буфер результатів, не виконуючи часткового спавну.
- **Zero Allocations**: Використовує внутрішні перевикористовувані буфери `batchExcludedCellsBuffer` та `priorityPositionsBuffer`, що усуває GC-алокації під час виконання в runtime.
- **Пріоритет зони спавну**: Спавн першочергово намагається зайняти позиції в межах прямокутника вихідної фішки (`parentPos` / `parentSize`), після чого розширює пошук у сусідні клітинки.

### Relocation Execution (`ChipsRelocate`)

Якщо `CanChipMoving` повернув `true`, виконується метод `ChipsRelocate` (приймає `IReadOnlyList<ChipMoveAction>`, що дозволяє уникати зайвого копіювання списків при виконанні `EvolutionPlan`):
1. **Очищення**: З клітинок прибираються посилання на фішку, що рухається (Source), та всі фішки з `plannedRelocations` (якщо список не порожній).
2. **Застосування налаштувань польоту**: Всім фішкам, що переміщуються (включаючи релоковані фішки та основну фішку), встановлюються відповідні налаштування польоту через `SetFlightSettings(flightSettings)`.
3. **Переміщення**:
   - Фішки, що релокуються, отримують нові координати.
   - Їм встановлюється стан руху (`SetMoving(true)`).
   - Оновлюється сітка (`fieldGrid.SetChipInCell`).
4. **Розміщення Головної Фішки**: Фішка, що ініціювала процес, ставиться на своє нове місце.

## Interaction with Other Systems

### 1. Drag & Drop
При завершенні перетягування (`OnDragEnd` в `DraggableChipLogic`):
- Викликається `ChipMovingLogic.ChipMoving`.
- Якщо релокація можлива, фішки розсуваються з налаштуваннями польоту `ChipFlightSettings.ChipRelocate` (політ із затримкою 0.6с та тривалістю 0.4с, траєкторія `HalfArcHalfBounce`).
- Якщо ні — фішка, яку тягнув гравець, повертається на попереднє місце ("snap back") з налаштуваннями `ChipFlightSettings.ChipSwap` (тривалість 0.6с, траєкторія `HalfArcHalfBounce`).

### 2. Evolution and Merge
При еволюції або злитті (зокрема через `Merge2Module` у `ChipEvolutionService.CanEvolve` → `ChipEvolutionPlanner`), коли результуючий чіп збільшується в розмірі, зміщується від меж поля або перетинає `cellsToExclude`:
- `ChipEvolutionPlanner` обмежує позицію в межах поля через `IChipMovingLogic.ClampCellToField`, перевіряє доступність позиції через `IChipMovingLogic.TryResolveCellPosition` (пріоритезуючи позиції з 0 релокацій: спочатку основна клітинка, потім 8 сусідів) і зберігає переміщення в `EvolutionPlan.PlannedRelocations`.
- Під час `ChipEvolutionService.Evolve` (`ChipEvolutionExecutor`) батьківська фішка знищується, сусіди релокуються через `ChipsRelocate` із налаштуваннями `ChipFlightSettings.ChipRelocate`.
- Основна нова фішка при збільшенні розміру створюється з `ChipFlightSettings.ChipGrow` (тривалість `0.3с`, затримка `0.6с`, лінійна траєкторія) та тригером `Triggers.GrowTrigger` (`MergeGrow`); при збереженні розміру й увімкненому `SpawnFlight.KeepPrimaryChipInPlace` — створюється на місці з `Triggers.SpawnTrigger`.
- Додаткові фішки (якщо провайдер повертає кілька) використовують `SpawnFlight.MultiChipFlightSettings` (для `Merge2Module` — `ChipFlightSettings.ChipRelocate`) та `Triggers.MultiSpawnTrigger`.
