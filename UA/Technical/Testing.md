# Testing

[← На Головну](../Main.md)


Проект використовує комбінацію Integration та Unit тестів для забезпечення стабільності.

## Integration Tests
> [!IMPORTANT]
> Інтеграційні тести підтримуються починаючи з версії Unity **6000.0**.

Розташовані в `Modules/Merge2/Tests/Scripts/Integration/`. Перевіряють роботу системи в зборі на реальному полі (або його емуляції).

### ChipBaseTests
Тести базової функціональності створення, переміщення та злиття чіпів.

#### CreateChip_SpawnChips
- **Мета**: Перевіряє коректність спавну чіпів різних розмірів через `ChipFactory` та `IFreeCellFinder`.
- **Сценарій**: Заповнює поле чіпами різних розмірів від центру, використовуючи `FindNearestFreeCell` для пошуку вільних клітинок. Перевіряє цілісність посилань між чіпами та клітинками після спавну.

#### CreateChip_DraggingChip
- **Мета**: Перевіряє коректність переміщення чіпів через drag-and-drop.
- **Сценарій**: Створює кілька чіпів на полі та симулює перетягування одного з них на іншу позицію. Перевіряє цілісність поля після переміщення.

#### DraggingChip_RandomMoves
- **Мета**: Перевіряє стабільність системи при великій кількості випадкових переміщень.
- **Сценарій**: Заповнює поле чіпами, потім виконує 2000 випадкових drag операцій між випадковими клітинками. Перевіряє цілісність поля після всіх операцій.

#### MergeableChip_NextChipIsBiggerThanParent
- **Мета**: Перевіряє коректність злиття чіпів, коли результуючий чіп більший за вихідні.
- **Сценарій**: Створює чіпи різних розмірів та симулює злиття меншого чіпа з більшим, що призводить до створення ще більшого чіпа. Перевіряє кількість чіпів та цілісність поля після злиття.

### ChipGeneratorTests
Тести функціональності ручного генератора чіпів (`IsAutoGeneration = false`).

#### ManualGenerator_SpawnsChipOnTapAndRecharges
- **Мета**: Перевіряє, що генератор створює чіпи при тапі, використовує заряди та коректно перезаряджається.
- **Сценарій**: Створює заряджений генератор, симулює тапи для використання всіх зарядів. Перевіряє, що чіпи були створені, генератор перейшов у стан перезарядки, а після очікування знову заряджений з відновленою кількістю зарядів.

#### ManualGenerator_EvolutionIntoNull
- **Мета**: Перевіряє, що генератор знищується після використання всіх перезарядок, коли `NextChipData = null`.
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `TotalRecharges = 1` через `GetSpecialData<ChipGeneratorData>()`. Використовує всі заряди генератора. Перевіряє, що генератор був знищений (клітинка порожня).

#### ManualGenerator_EvolutionIntoNextChip
- **Мета**: Перевіряє, що генератор еволюціонує в `NextChipData` після використання всіх перезарядок.
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `TotalRecharges = 1` та `NextChipData` через `GetSpecialData<ChipGeneratorData>()`. Використовує всі заряди. Перевіряє, що генератор замінився на `NextChipData`.

#### ManualGenerator_NoSpace
- **Мета**: Перевіряє поведінку генератора при спробі створити чіп, коли на полі немає вільного місця.
- **Сценарій**: Заповнює поле повністю, залишаючи тільки клітинку з генератором. Симулює тап на генератор. Перевіряє, що новий чіп не був створений.

#### ManualGenerator_StartsUncharged_Recharges
- **Мета**: Перевіряє поведінку генератора, який починає без заряду (`IsStartCharged = false`).
- **Сценарій**: Створює незаряджений генератор, чекає час перезарядки, симулює тап. Перевіряє, що генератор заряджається та створює чіп після тапу.

#### ManualGenerator_StartsUncharged_Recharges
- **Мета**: Перевіряє поведінку генератора, який починає без заряду (`IsStartCharged = false`).
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `IsStartCharged = false` через `GetSpecialData<ChipGeneratorData>()`. Чекає час перезарядки, симулює тап. Перевіряє, що генератор заряджається та створює чіп після тапу.

### AutoChipGeneratorTests
Тести функціональності автоматичного генератора чіпів (`IsAutoGeneration = true`).

#### AutoGenerator_SpawnsChipAutomaticallyBeforeCharge
- **Мета**: Перевіряє, що автоматичний генератор створює чіпи автоматично протягом усього циклу зарядки.
- **Сценарій**: Створює заряджений автоматичний генератор, чекає інтервали генерації. Перевіряє, що всі чіпи (згідно з `ChargeCount`) були створені автоматично до повної розрядки.

#### AutoGenerator_SpawnAround
- **Мета**: Перевіряє, що автоматичний генератор створює чіпи тільки навколо себе (у сусідніх клітинках).
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `ChargeCount = 100` через `GetSpecialData<ChipGeneratorData>()`. Чекає генерацію 10 чіпів. Перевіряє, що всі чіпи створені навколо генератора (всього 11 чіпів на полі).

#### AutoGenerator_EntersWaitingStateDuringDrag
- **Мета**: Перевіряє, що генератор переходить у стан очікування під час перетягування.
- **Сценарій**: Створює заряджений генератор, починає перетягування генератора. Перевіряє поведінку генератора під час та після перетягування.

#### AutoGenerator_StartsUncharged_RechargesAndGenerates
- **Мета**: Перевіряє поведінку автоматичного генератора, який починає без заряду.
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `IsStartCharged = false` через `GetSpecialData<ChipGeneratorData>()`. Чекає час перезарядки. Перевіряє, що генератор автоматично створив чіп після перезарядки.

#### AutoGenerator_Evolution_IntoNull
- **Мета**: Перевіряє знищення автоматичного генератора після використання всіх перезарядок, коли `NextChipData = null`.
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `ChargeCount = 2` та `TotalRecharges = 1` через `GetSpecialData<ChipGeneratorData>()`. Чекає завершення всіх циклів генерації. Перевіряє, що генератор був знищений (клітинка порожня).

#### AutoGenerator_Evolution_IntoNextChip
- **Мета**: Перевіряє еволюцію автоматичного генератора в `NextChipData` після використання всіх перезарядок.
- **Сценарій**: Створює копію ChipData через `Clone()`, встановлює `ChargeCount = 2`, `TotalRecharges = 1` та `NextChipData` через `GetSpecialData<ChipGeneratorData>()`. Чекає завершення всіх циклів. Перевіряє, що генератор еволюціонував у `NextChipData`.

### ChipContainerTests
Тести функціональності контейнера для чіпів (`ChipContainer`).

#### SpawnChipContainer_And_GoldGenerator
- **Мета**: Перевіряє взаємодію контейнера з генератором золота, включаючи споживання чіпів та автоматичне спавнення.
- **Сценарій**: Створює контейнер та генератор золота. Симулює перетягування золотого чіпа в контейнер. Перевіряє, що генератор продовжує спавнити нові чіпи, а контейнер успішно приймає їх. Валідує цілісність поля після всіх маніпуляцій.

#### Container_Filling
- **Мета**: Перевіряє процес заповнення контейнера чіпами.
- **Сценарій**: Створює контейнер на позиції (1, 1). Створює 3 різних чіпа (water_1_1, water_1_2, water_2) та послідовно перетягує їх у контейнер. Перевіряє кількість чіпів на полі (має бути 1 - сам контейнер) та консистентність поля.

### ChipPowerBoosterTests
Тести функціональності чіпа-підсилювача ([ChipPowerBooster](../Chips/ChipPowerBooster.md)) та системи підписок.

#### SpawnAndMovingCheckSubscribe
- **Мета**: Перевіряє коректність підписок бустера після спавну та серії drag-переміщень.
- **Сценарій**: Створює бустер на позиції (0,0), перевіряє очікувані `ObservedCellPositions`. Виконує 3 послідовних переміщення та після кожного валідує список підписаних клітинок через `CellObserverAssertions.AssertObservedCells`.

#### AddGeneratorAndMoveBoosterCheckSubscribe
- **Мета**: Перевіряє підписки та virtual-позиції при наявності генератора на полі та переміщенні бустера.
- **Сценарій**: Створює генератор та бустер. Перевіряє, що клітинки під генератором розділені на direct та virtual. Виконує 2 переміщення бустера та валідує оновлення підписок.

#### AddGeneratorAndMoveGeneratorCheckSubscribe
- **Мета**: Перевіряє apply/remove модифікаторів при переміщенні генератора відносно бустера.
- **Сценарій**: Створює генератор далеко від бустера — перевіряє `BoostedTargets.Count == 0`. Переміщує генератор поруч з бустером — перевіряє `BoostedTargets.Count == 1` та `AppliedBoosters.Count == 1`. Переміщує генератор на бустер та від нього — перевіряє динамічне оновлення підсилень.

#### CheckBoosterPower
- **Мета**: Перевіряє, що один `ChipPowerBooster` прискорює одночасно manual і auto генератори в зоні впливу.
- **Сценарій**: Створює manual-генератор (`IsStartCharged = false`, `ChargingTime = 5f`) і auto-генератор (`ChargingTime = 5f`), ставить бустер так, щоб обидва потрапили в range. Після очікування `ChargingTime / Power` перевіряє, що manual-генератор став `IsCharged == true`, а auto-генератор перейшов у заряджений цикл (`RuntimeDataOnlyEditor.ChargeCount != 0`).

#### CheckBoosterPower_MoveGenerator
- **Мета**: Перевіряє, що модифікатор знімається при переміщенні генератора від бустера.
- **Сценарій**: Створює незаряджений генератор поруч з бустером (`BoostedTargets.Count == 1`) з параметрами через `GetSpecialData<ChipGeneratorData>()`. Переміщує генератор далеко. Чекає `ChargingTime / Power - timeToMove`. Перевіряє, що генератор **не** зарядився (підсилення було знято).

#### CheckGeneratorReturnsToBoosterRangeAfterLockedMove
- **Мета**: Перевіряє, що генератор і бустер повертаються до свого діапазону впливу після невдалого переміщення на `MoveLocked` чіп (snap-back).
- **Сценарій**:
  1. Розміщує генератор на позиції (0, 0) і бустер на позиції (4, 0) — генератор у зоні дії бустера (`AppliedBoosters.Count == 1`).
  2. Створює `Fire_1`-чіп на позиції (8, 0) з ефектом `EffectConsts.Blockers.MoveLockedEffect` у `EffectEnables`.
  3. Симулює перетягування **генератора** на `Fire_1` — переміщення блокується, генератор snap-back до (0, 0).
  4. **Ключова перевірка**: Після snap-back — `AppliedBoosters.Count == 1` і `BoostedTargets.Contains(generatorChip)` — підсилення відновлено коректно.
  5. Симулює перетягування **бустера** на `Fire_1` — переміщення блокується, бустер snap-back до (4, 0).
  6. **Ключова перевірка**: Після snap-back — `AppliedBoosters.Count == 1` і `BoostedTargets.Contains(generatorChip)` — підсилення не втрачено.
- **Важливість**: Гарантує, що `DraggableChipLogic` коректно reapply-є бустерів при snap-back через `OnChangedCell` після невдалого переміщення на `MoveLocked` ціль.

#### CheckBoosterPower_Evolution
- **Мета**: Перевіряє коректність очищення підсилення при еволюції (злитті) бустера, що впливає на роботу сусідніх генераторів.
- **Сценарій**:
  1. Розміщує uncharged генератор на позиції (0, 0) з `ChargingTime = 5f`.
  2. Створює два бустери на позиціях (4, 0) і (4, 6), обидва з `boosterEvolutionChipData` (конфігурація, яка має merge результат).
  3. Генератор знаходиться в діапазоні першого бустера → `AppliedBoosters.Count == 1`.
  4. Перетягує другий бустер на перший (drag з (4, 6) на (4, 0)) — це викликає **злиття/еволюцію** бустерів.
  5. **Ключова перевірка**: Після merge генератор повинен мати `AppliedBoosters.Count == 0` (старий бустер знищений та очистив підсилення).
  6. **Верифікація**: Чекає час `ChargingTime - timeToMove`. Генератор залишається UNCHARGED, оскільки підсилення було знято при знищенні першого бустера.
- **Важливість**: Гарантує, що `PowerBoosterCellSubscriber.OnChipDestroy()` коректно видаляє всі підсилення перед знищенням бустера, щоб не залишати "привидів" активних бустерів у генераторів.

## Instrumentation (Helpers)

### TestSettings
Класс-конфігурація для тестових налаштувань.
- **Призначення**: Зберігає шлях до префабу тестової сцени та прапорці для дебагу.
- **Оновлення**: 
  - Додано пункт меню `Window/Expecto/MergeBase/Tests/Enable Debug Mode` для швидкого ввімкнення режиму налагодження.
  - Додано посилання на `ChipCreatorSettings` для автоматичного налаштування шляхів до даних та префабів під час виконання тестів.

### Automated Scaffolding
Інструмент "New Game Folder" автоматично створює:
- `{folderName}Tests.cs`: Шаблон інтеграційного тесту.
- `{folderName}.Tests.asmdef`: Налаштований Assembly Definition для тестів.
- `Test{folderName}Settings.asset`: Налаштування для Resource loading.

### TestFieldBuilder
Клас-помічник для створення тестового оточення.
- **Використання**: Завантажує префаб `TestElemental_Field`, налаштовує DI Container та ініціалізує поле.
- **Конфігурація**: Використовує `TestSettings` через Resource loading для визначення префабу сцени та режимів налагодження.
- **Ізоляція**: Метод `ClearField()` дозволяє очистити поле між тестами без перезавантаження сцени.

### FieldAssertions
Набір методів для валідації стану поля.
- `AssertFieldConsistency(field)`: Перевіряє цілісність посилань:
  - Чи кожна фішка в `MainCell` коректно посилається на свої `SecondaryCells`.
  - Чи всі клітинки під фішкою мають правильні посилання на цю фішку.
  - Чи немає "фантомних" блокувань.

### TestHelper
Статичний клас з допоміжними методами для тестів.
- `FindChipByChipId(field, chipId, exclude)`: Знаходить на полі вказаний чіп за його назвою (ID), дозволяючи виключити вже знайдені чіпи.
- `WaitForSingleRun()`: Пауза для візуального контролю при запуску одного тесту вручну.

## Test Writing Principles
1. **Clean Slate**: Кожен тест має починатися з чистого поля.
2. **Real Input Simulation**: Використовуйте `InputHelper` для емуляції кліків/drag, замість прямого виклику методів логіки (де це можливо), щоб тестувати повний пайплайн.
3. **Assert Consistency**: Після кожної складної маніпуляції (Merge, Move) викликайте `AssertFieldConsistency`.
